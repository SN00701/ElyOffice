## 1. 这是什么

一个 Windows x64 上的统一办公套件：**一个安装包、一个启动器、一个窗口**，六类文件在同一个标签条里混排
（文字、表格、演示、PDF、Markdown、文本）。需求与验收基线在 `00-需求优化与验收基线.md`，
决策在 `03-架构决策记录ADR.md`，对抗式审查在 `08-对抗式审查报告.md`。

## 4. LibreOffice（LOK）在 Windows 上的构建：20 道坎

构建脚本：`scripts/build-libreoffice-win.sh`（真正的构建）与 `scripts/build-lo-win-run.sh`（以干净环境跑它，
日志写 `F:\mpely-lo\build.log`）。源码在 `F:\mpely-lo\src`（无空格路径），补丁序列 0001–0060
（`patches/libreoffice/`），`scripts/apply-lo-patches.sh` 自己认得已打到第几条。

跨过的坎（每一条都留在脚本或补丁里，详见 `07-开发计划与里程碑.md` §4.2）：

| # | 障碍 | 解法 |
| --- | --- | --- |
| 1–9 | 含空格的源码路径、partial clone 的按需取 blob、缺 Windows 原生 `pkgconf`、VS 2026 不注册旧组件 ID、VS 路径含空格、最新工具集没有编译器、编译器找不到标准库头、缺 clang-cl | 见 `07` 的表格；补丁 0054 与构建脚本 |
| 10 | 编译器的 include 清单被写进构建的命令，路径带空格与括号，shell 瘫掉 | 构建不导入这个变量（构建自己有 `SOLARINC`） |
| 11 | MSBuild 找 Visual Studio 2026 的 C++ 目标（v180），本机只有 v170，且那个目录改不了 | 环境变量 `VCTargetsPath` 指向 v170；`make VCTOOLSET=v143` |
| 12 | 环境里两个只差大小写的同名变量，MSBuild 抛"已添加项" | 导入时按大小写不敏感去重 |
| 13 | 构建去取字体（NotoSans 112MB、NotoSerif 67MB，直连约 30KB/s） | `BUILD_TYPE` 去掉 `MORE_FONTS`；补丁 0055 把模块清空 |
| 14 | 外部依赖一个一个取 | `scripts/fetch-lo-tarballs.sh` 并行取并按散列核对 |
| 15 | MSBuild 找 Visual Studio 2022（VS2022 未装），CMake 拿不到 Cygwin 路径的编译器 | 补丁 0056（curl 用 NMake 生成器）、0058（meson 用 Windows 路径） |
| 16 | `PKG_CONFIG=`（空值）让 autoconf 跳过查找 | 指向自写的替身（`scripts/pkgconf-stub.rs`），替身答"构建自有的那些包在" |
| 17 | 外部构建继承 make 的 `MAKEFLAGS`（含 `-j16`），nmake 读成自己的参数 | 补丁 0057：外部构建清掉 `MAKEFLAGS`，并拿到编译器的文件夹 |
| 18 | xmlsec 的头文件在代码页 936 下有字符，警告被当错误 | 补丁 0059：`/wd4819` |
| 19 | ActiveX 扩展要 Visual Studio 的 ATL 头（本机没有，且改不了安装目录） | 补丁 0060：不建这一部分 |
| 20 | 树的补丁状态与补丁序列对不上（补丁会新增文件） | 构建脚本先把树复位（`git checkout -- .` 并去掉补丁新增的文件） |

**续跑**：

```bash
F:\cygwin64\bin\bash.exe '/cygdrive/e/trae pg/office_modpack/mpelyoffice/scripts/build-lo-win-run.sh'
```

## 6. 怎么接着做

1. **内核**（最要紧）：把 §4 的构建跑完，`mp-lok-roundtrip.ps1` 验证 DOCX 真的能打开；之后接编辑与保存的往返。
2. **编辑器的外壳**：`crates/ely-office`（上游的文档外壳）接进 `apps/mpelyoffice`，让标签共用一个会话。
3. **自动保存与恢复副本**：复用上游的 `ely_office::Recovering`。
4. **Windows 的细节**：`AppUserModelID` ✓ 已有；多显示器与 200% DPI 未验；打印未接。
5. **发布**：签名（OV 证书或 Azure Artifact Signing）、干净虚拟机上的单包验收、许可清单随内核更新。

## 7. 本 fork 的规矩（在 `AGENTS.md` 的 MPelyoffice 一节）

1. 许可红线：分发物只允许 MIT / BSD-2/3 / Apache-2.0 / MPL-2.0；**MuPDF(AGPL) 与 `pdfium-rs`(GPL) 不得进包**。
2. 字体不再分发：LO 构建去掉 `--with-fonts`，缺字体走回退并提示。
3. 绝不夺取文件默认关联：只写 `OpenWithProgids` / `RegisteredApplications`。
4. 文档归用户：卸载只动程序目录与本应用的数据目录。
5. 数据完整性优先：原子写、外部修改不覆盖、编码保真、关闭前询问未保存。
6. 诚实：未实现的能力在状态栏与支持矩阵里写明，不做假动作。
7. 开始页即入口；控件一律用组件库，文案一律走 i18n。
