# MPelyoffice 性能记录

版本：0.1
日期：2026-10-22
机器：Windows 11 x64，1536×864，显示 125%，开发构建与发行构建各测
量法：`tests/scripts/mp-perf.ps1`（起程序→等窗口→量内存→量放着不管时的计算）

---

## 1. 数字

| 指标 | 开发构建 | 发行构建 |
| --- | --- | --- |
| 起到窗口（中位数，10 次） | 1857 ms | **492 ms** |
| 起到窗口（最慢的一次） | 3504 ms | 1000 ms |
| 窗口单独的内存 | 92.7 MB | **81.6 MB** |
| 带一个文档的内存 | 94.2 MB | **82.2 MB** |
| 放着不管时 10 秒内的计算 | 0.31 s | **0.14 s** |

读法：
- 窗口在**半秒**上下开出来（发行构建 ✓）；开发构建慢四倍，是没有优化的缘故 ✗（不算数 ✗）。
- 空窗口占 **81.6 MB** ✗——组件库的字体与图块缓存占了大头 ✗（上游的记录里同样在几十到几百 MB 之间 ✗）。
- 打开一个 PDF 之后只多 **0.6 MB** ✓（逐页渲染的图块按需进 ✗）——分页 virtualization 生效 ✓。
- 放着不管时 10 秒用 **0.14 s** 的计算（1.4%）✓——没有轮询、没有空转 ✓。

## 4. 怎么再量

```powershell
# 发行构建
powershell -ExecutionPolicy Bypass -File tests\scripts\mp-perf.ps1 `
  -Program F:\mpely-target\release\mpelyoffice.exe -Runs 30
```

机器上若有别的重活在跑（编译、取包），数字会偏大 ✗——量之前先看 `Get-Process | Sort-Object CPU` ✓。
