# MPelyoffice 竞品对标（2026-10 实证）

版本：0.1
日期：2026-10-20
方法：当日抓取厂商一手页面 + 应用商店条目 + 官方更新清单。标注 **[已核实]** 为今日直接取证，
标注 **[推断]** 为基于已核实事实的推论，标注 **[未核实]** 为未能取证、需后续确认。

---

## 0. 结论先行

1. **没有任何可信厂商用"每格式一个引擎"来做整合套件**。WPS / ONLYOFFICE / Zoho / Collabora
   都是**一套统一外壳 + 一套文档内核**，按扩展名派发到对应编辑器。MPelyoffice 走同一路线：
   **外壳统一，内核按格式可插拔**。
2. **"单窗口多标签"是 2026 年仍未被微软占据的护城河**。WPS 把它做成了核心卖点
   （"整合模式"），微软至今 Word/Excel/PowerPoint 无原生多标签 [已核实，见 §2.3]。
3. **文件默认关联在 Win10/11 上不可能被程序夺取**。`UserChoice` 哈希受保护且对所属用户 DENY 写，
   Win11 25H2 的 UCPD 驱动主动拦截 [已核实，见 §4.1]。这是硬约束，不是实现难度问题。
4. **AGPL 是分发红线**：MuPDF、Ghostscript、ONLYOFFICE 都不可进入面向外的免费分发包 [已核实，见 §3.1]。
5. **AI 入口必须唯一**，且应是外壳的能力而非独立应用 [已核实：微软 2026 年把 Copilot 收敛为两个入口]。

## 2. 重点对标

### 2.1 WPS —— 主对标对象

**窗口模型**（[已核实] WPS 帮助中心「Tabbed Viewing Feature」「Open multiple documents」）：
- 两种模式：**整合模式**（All-In-One Mode）与多组件模式；切换需重启。
- 整合模式下，文字/表格/演示/PDF 四个组件**塌缩为一个桌面图标**，文档作为**混合类型标签页**
  聚合在同一框架内。
- 标签可**拖出**成独立窗口，也可拖回合并。
- 可把标签存入**命名工作区**，跨重启恢复。

**标签交互细节**（[已核实]）：
| 交互 | 行为 |
| --- | --- |
| 双击标签 | 关闭该标签 |
| 双击标签栏空白 | 新建文档 |
| `+` 按钮 | 新建文档 |
| Ctrl+N | 新建文档 |
| Ctrl+Tab / Ctrl+Shift+Tab | 循环标签 |
| 右键标签 | 全部保存 / 全部关闭 / 关闭其他 / 重命名 |

> **抄什么**：混合标签、拖出/拖回、工作区、上表全部交互细节。
> **不抄什么**：WPS 的云、账号、会员墙、AI 面板——本项目首版明确不做云与账号。

**多开与单实例的平衡**（[已核实] WPS 论坛资料）：WPS 同时支持"多开"（同 exe 多个独立顶层窗口）
与标签模式。因此 MPelyoffice 也必须**两者都支持**：一个 exe 家族，可开多窗口。

**AI**（[已核实] wps.cn 2026 特性页）：WPS 灵犀覆盖拼写/语法分类解释、代码块高亮、
AI 标题识别、公式错误自动修正（如 `#SPILL`）、AI 格式刷、PPT 智能配色、PDF 全文与图片翻译、
扫描 PDF OCR、文档摘要、**保持版式的并行翻译**。
> **启示**：AI 能力要长在外壳上（格式刷、并行翻译、公式纠错这类"外壳 + 内核"协同的事，
> 通用聊天机器人做不了），而不是塞一个聊天侧栏。

### 2.2 ONLYOFFICE —— 技术对标对象

- **三通道分发**（[已核实] 其 `appcast.json` 公布 `archive`/`iss`/`msi` 三种产物）：
  EXE（Inno Setup，`/silent /update`）、MSI（`/qr /norestart`）、1MB 在线包。
  > **抄什么**：**同时提供 EXE 与 MSI**，静默参数标准化。
- **自研内核**（[已核实] GitHub DesktopEditors README），非 LibreOffice。
- **Document Builder**（[已核实]）：独立的无头文档生成/编辑 SDK + CLI，覆盖
  docx/odt/rtf/txt/dotx/ott/html/form/pptx/ppt/odp/ppsx/potx/otp/xlsx/xls/ods/csv/xltx/ots/pdf/djvu/xps/pdfa/jpg/png/bmp。
  > **抄什么**：无头 API 是批量转换、打印管线、AI 流水线的基础。本项目对应物是
  > `ely-lok` 的 worker 进程 + `ely-pdf-engine` 的 IPC 协议。
- **插件目录契约**：`%ProgramFiles%\...\editors\sdkjs-plugins\<GUID>\config.json`，插件市场 + 本地 zip 安装。
- **公开格式支持矩阵**（[已核实] 帮助中心 supportedformats）：四轴——原生查看 / 转换后查看 / 原生编辑 / 转换后编辑。
  > **抄什么**：这是本项目 §R5 的落地形式，也是**诚实竞争**的唯一做法。
- **10.0 安全修复**（[已核实] changelog）：DOCX 超链接 XSS、压缩包解压任意文件写、HML 路径穿越、
  EPUB 转换本地文件读、Document Builder `native.GetFileBinary` 读本地文件、`/ai-proxy` SSRF。
  > **启示**：整合套件是攻击面放大器，这些 CVE 全部发生在"解析不可信文档"路径上，
  > 对抗式审查必须逐条对照。

### 2.3 Microsoft 365 —— 部署与 AI 入口对标

- **ODT**（[已核实]）：3.4MB 自解压 `setup.exe` + `configuration.xml`，用 `<Product>`/`<ExcludeApp>`
  选组件、选语言、选通道；`/download` 与 `/install` 分离。
  > **抄什么**：可编程部署。本项目安装器对应物：`MPelyoffice-Setup.exe` + 可选 `config.xml`
  >（选择组件/路径/是否创建关联）。
- **Click-to-Run 管理接口**（[已核实]）：`CLSID_UpdateNotifyObject` / `IUpdateNotify`，
  暴露 `GetBlockingApps()` / `GetOfficeDeploymentData()`，供第三方补丁管理器集成；**调用需提权**。
- **AI 入口收敛**（[已核实] 2026-05/2026-06 官方博客与 release notes）：Copilot 收敛为**两个入口**
  （右下角画布按钮 + 选中时的上下文入口），统一 `Alt+C` / `F6`。
  > **抄什么**：AI 只有一个入口，不要在多个位置放多个入口。
- **微软自己没做多标签**（[已核实] 微软 Answers 问答页，截至 2026-10 仍无原生多标签）。

### 2.4 Zoho Office Desktop（2026-09 新品，最有参考价值）

（[已核实] Zoho 官方 journal 与产品页）
- **一个入口取代四个独立安装**；安装向导可**选择要装哪些应用**。
- "真正离线、不需要账号、不需要登录"；但**首次安装与首次启动需要联网**。
- Writer 桌面版有**标签式文档视图**与单页视图；支持 DOCX/ODT/TXT/**Markdown**。
- 定价：个人免费；Business $10/设备。
> **抄什么**：① 组件可选安装 = 免费版的"精简档"免费送；② "无账号、真离线"是明确写在包装上的转化卖点；
> ③ Markdown 已是一等公民格式。

### 2.5 Collabora / LibreOffice / OpenOffice —— 派发模型与代价

- **Start Center 派发**（[已核实] LibreOffice 帮助）：最近文档按"保存它的模块"打开，
  模板与新建按钮按应用分组。**文件类型 → 模块的派发就是 WPS/ONLYOFFICE/Zoho 内部同一套机制。**
- **Collabora Office**（[已核实] 新闻稿与产品页）：**去掉 Java 依赖**，单一自包含下载，
  Web UI + 标签式界面；Collabora Office Classic 保留 VCL 界面与 Java。26.04 新增
  Writer/Calc/Impress 的"复制粘贴为 Markdown"。
- **OpenOffice**（[已核实]）：**仍只有 32 位 Windows 二进制**，原生 x64 计划在 OpenOffice 5；
  且**不能保存 OOXML**（[已核实] 官网 FAQ）。项目方向：现代 MSVC 工具链、OpenSSL 3、内置 Python 3.11、
  新的 C++/UNO 桥接、macOS 签名与公证。
- **LibreOffice Portable**（[已核实] PortableApps）：`.paf.exe` 自解压，213MB，零安装。
  > **启示**：便携/免安装形态有真实需求，MPelyoffice 可提供"绿色版"变体（同一 payload，不同启动方式）。

## 3. 技术路线对标（内核选型）

### 3.1 PDF 内核：AGPL 红线必须处理

| 内核 | 许可 | 事实 | 结论 |
| --- | --- | --- | --- |
| **MuPDF** | AGPL-3.0 | Artifex 官网原话："Embedding this in a product? MuPDF is AGPL — contact us for a commercial license" [已核实]。NuGet 包 `MuPDF.NET` 3.28.0 用的是 **Artifex Community License（非商用）** [已核实] | **不得进入闭源/免费分发二进制**，除非签署 OEM 商业许可 |
| **PDFium** | BSD-3-Clause | Chromium 的 PDF 渲染器；仅要求保留版权声明 [已核实] | **选定**。注意两个陷阱：① Rust 封装 `pdfium-rs` 是 **GPL-2.0-or-later**（会污染二进制）[已核实]；② `documentcloud/pdfium` 分支带"不得用 PDFium 名义推广"的命名条款 [已核实] |
| **PDFBox** | Apache-2.0 | Java 依赖，需带 JRE [已核实] | 不选（体积） |
| **Ghostscript** | AGPL | 同 MuPDF 问题 | 不选 |

### 3.2 OOXML 内核的现实

（[已核实] 各库自述）
| 库 | 许可 | 能否改现有文件 | 结论 |
| --- | --- | --- | --- |
| `docx-rs` | MIT | 否，**是写入器**（"A .docx file writer"） | 不可用于编辑既有文档 |
| `rust_xlsxwriter` | MIT | 否，**明文"cannot be used to modify an existing file"** | 同上 |
| `calamine` | MIT | 否，**只读且丢弃格式** | 只读 |
| Open XML SDK | MIT | 是（DOM + 保留未知元素） | .NET 路线可用 |
| Aspose / Spire / GemBox / Syncfusion | 专有 | 是 | **按部署计费**（Aspose "1 Developer And 50 Commercial Deployments" 是一档真实 SKU）[已核实]，免费分发不适用 |

> **结论（与已选路线一致）**：Rust 生态没有可用的"无损改写既有 DOCX"内核；
> 要么买（贵，且按部署计费），要么自研（10 年量级），要么**借用成熟文档内核**——
> 本项目选择第三条：**LibreOfficeKit**，并接受"必须自建带 LOK 的 LibreOffice"的构建税，
> 同时用 §2.2 的**支持矩阵**诚实标注能力边界。

## 4. Windows 集成机制对标（硬约束）

### 4.1 文件关联：能不能夺取默认

（[已核实] Microsoft Learn 与 Mozilla 源码）
- 每用户默认存于 `HKCU\...\Explorer\FileExts\<ext>\UserChoice`，含 `ProgId` 与 `Hash`；
  **该键对所属用户是 DENY 写**（文件句柄）。
- `Hash` 是 Windows 对「扩展名 + 用户 SID + ProgID + 键 FILETIME + 固定 GUID 字符串」的摘要，
  算法未公开；只写 `ProgId` 不写匹配 `Hash`，**Windows 会丢弃并重置**。
- 微软官方安装器指引：注册 ProgID → 写 `OpenWithProgids` → 注册 `RegisteredApplications`；
  **卸载时"保持文件类型映射不变"**（原文：leaving file type mappings unchanged avoids …）。
- 写完后调用 `SHChangeNotify(SHCNE_ASSOCCHANGED)`，否则资源管理器可能不刷新。

> **决策**：MPelyoffice **永不写 `UserChoice`**；应用内"设为默认"按钮**跳系统设置**
> （`ms-settings:defaultapps`），由用户完成。卸载不碰 `HKCR\.<ext>` 的默认值。

### 4.2 单实例与 IPC

（[已核实] MS Learn / Mozilla 文档）
| 机制 | 结论 |
| --- | --- |
| 命名互斥体 | 首选。`Global\` 机器级、`Local\` 会话级；**RDP 多会话下 Local 互斥体不互斥** |
| 命名管道 | 首选的传参通道；**默认跨会话可达**，需 `CurrentUserOnly` 或显式安全描述符，并建议把会话 ID 编进管道名 |
| WM_COPYDATA | 需先拿到 HWND，载荷 32KB 上限，低完整性进程会被 UIPI 拦 |
| DDE | Win3.x 遗产，不新用 |
| `DelegateExecute` | 需 COM 进程内服务器，徒增复杂度，不采用 |

> **决策**：互斥体名 `Global\MPelyoffice.{SID}`（带显式 ACL）+ 管道名 `\\.\pipe\MPelyoffice.{SID}.{SessionId}`，
> 载荷为 JSON 命令（`{"verb":"open","paths":[...]}`）。

### 4.3 打包技术

（[已核实] Microsoft Learn 与各工具官网）
- **MSIX**：禁止驱动与按用户服务；注册表/文件系统写入被虚拟化；包目录只读；原生 C++ 需声明 VCLibs 依赖；
  **不会接管已有默认程序**；`WindowsApps` 目录 ACL 锁定，用户无法放插件。
  > **不作为唯一分发通道**，最多作为 Store 附加通道。
- **Inno Setup**：单一 EXE、LZMA2 压���、天然支持 `HKCU`/`OpenWithProgids` 注册表写入、
  `PrivilegesRequired=lowest` 支持免管理员按用户安装、静默参数 `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`。
- **WiX/MSI**：企业 GPO/SCCM 分发友好，有回滚；写文件关联用原生表。
- **NSIS**：体积更小，PortableApps 生态即此系。

> **决策**：主分发 = **自研 per-user 引导器**（免管理员、单 EXE、可编程、无外部工具链依赖），
> 后续补 **WiX MSI** 作为企业通道；**MSIX 不做**（与原生 DLL/插件目录/关联诉求冲突）。
> `winget` 已确认可提供 Inno Setup 6.7.3，作为"若不想自研"的备选。

### 4.4 代码签名与 SmartScreen（2026 已变化）

（[已核实] Microsoft Learn，文档日期 2026-05）
- **EV 签名自 2024 年起不再即时豁免 SmartScreen**，与 OV 走同一套信誉积累流程。
- 信誉按**发布者身份 + 文件哈希**双维度；**每次新构建哈希都归零**，除非用同一发布者身份签名。
- 微软推荐 **Azure Artifact Signing**（约 $9.99/月，无需 USB 令牌，适合 CI）。
- 商店通道无 SmartScreen 提示。

> **决策**：MPelyoffice 首版**不内置签名**（无证书），但：① 全部二进制组件保持可签名的独立文件；
> ② 发布手册写明签名流程；③ 应用内"安装帮助"页说明 SmartScreen 预期；④ 预留 EV/OV/Azure 接入位。
