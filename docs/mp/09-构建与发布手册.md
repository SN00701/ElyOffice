# MPelyoffice 构建与发布手册（Windows x64）

版本：0.1
日期：2026-10-20
适用：从零在 Windows 10 1809+ / Win11 x64 上构建出可分发的 MPelyoffice 安装包

---

## 0. 首次使用速通

```powershell
# 0) 网络：本机直连 GitHub 仅 ~20KB/s，须走本地代理（否则源码与 crates 拉取要数小时）
$env:HTTPS_PROXY='http://127.0.0.1:7897'; $env:HTTP_PROXY='http://127.0.0.1:7897'
$env:CARGO_NET_GIT_FETCH_WITH_CLI='true'

# 1) MSVC 环境（VS 2026 在 D: 盘，须显式注入；cargo 的自动探测可能找不到非标准盘）
& "D:\Program Files\Microsoft Visual Studio\18\Community\Common7\Tools\VsDevCmd.bat" -arch=x64 -host_arch=x64

# 2) 构建（target 放无空格、大容量盘；工具链用已装的那一份）
$env:CARGO_TARGET_DIR='F:\mpely-target'
$env:RUSTUP_TOOLCHAIN='1.98.1-x86_64-pc-windows-msvc'
cargo build --release -p mpelyoffice -p mpelyoffice-setup

# 3) 组分发包（带许可清单与逐文件散列）
$env:PYTHONUTF8='1'
powershell -ExecutionPolicy Bypass -File packaging\windows\stage.ps1 -TargetDir F:\mpely-office-dist

# 4) 装 → 跑 → 卸 的验收
powershell -ExecutionPolicy Bypass -File tests\scripts\mp-install.ps1 `
  -Setup F:\mpely-office-dist\MPelyoffice-Setup.exe -Payload F:\mpely-office-dist
```

## 2. LibreOffice（LOK）在 Windows 的构建

上游 `scripts/build-libreoffice.sh` 已含 `CYGWIN*` 分支；本项目另有两个脚本走同一条路：
`scripts/build-libreoffice-win.sh`（真正的构建）与 `scripts/build-lo-win-run.sh`（以干净环境跑它，日志写 `F:\mpely-lo\build.log`）。

| 步骤 | 内容 |
| --- | --- |
| 1 | 稀疏取 LO 源码（仅补丁触及的路径）：`scripts/fetch-references.sh` 里的 `libreoffice-core`，commit `8221e31b`；按补丁清单补取 blob |
| 2 | 打 Ely 补丁：`scripts/apply-lo-patches.sh <lo-src>`（补丁序号 0001–0055；脚本自己认得已打到第几条） |
| 3 | Cygwin 中 `./autogen.sh` 并传 Windows 选项：`--with-visual-studio=2026 --disable-ccache --disable-cli --without-dotnet`，并剔除 Unix 专用开关 |
| 4 | **清除 Git Bash 注入的环境变量**：`MSYSTEM`、`MSYSTEM_PREFIX`、`MINGW_PREFIX`、`MSYSTEM_CHOST`、`MSYSTEM_CARCH` |
| 5 | `PATH=/opt/lo/bin:$PATH`（用 Cygwin 自己的 make，不用 Git Bash 的） |
| 6 | 从 `config_host.mk` 的 `BUILD_TYPE` 里去掉 `MORE_FONTS`（见下） |
| 7 | `make -j16` |
| 8 | 构建后处理：只保留 `dict-en` 词典；**剥离 Lightproof（Python）**（Windows 必带内置 Python，第二次启动会挂起）；注入 `packaging/libreoffice/ely.xcd` |

**Windows 专属补丁（必须包含）**：
- `0044-lok-win32-paints-then-copies.patch`：Win32 虚拟设备无 `SetSizeUsingBuffer`，须先按全尺寸画进设备再拷进客户缓冲区。
  缺失时表格只画 1×1 像素（表现为"全黑无网格线"）。
- `0054-lok-find-msvc-vs2026.patch`：VS 2026 的工具集与 `realpath -s` 的差异，configure 找不到编译器时先看它。

**字体不取（省数小时）**：`MORE_FONTS` 决定构建是否去取 Noto、DejaVu、Liberation 等字体族。
本机直连 `dev-www.libreoffice.org` 只有约 30KB/s，光 NotoSans（112MB）与 NotoSerif（67MB）就各要四十多分钟。
分发物不带字体（见 `AGENTS.md` 的 MPelyoffice 规则 2），所以：
- 补丁 `0055-no-more-fonts.patch` 把 `external/more_fonts` 的目标清单清空；
- 构建脚本在 `make` 之前把 `config_host.mk` 里 `BUILD_TYPE` 的 `MORE_FONTS` 去掉（`fetch_Optional` 由此不再下载）。

字体只用于字体框的列表与测试样本；内核用运行它的机器上的字体排版。

**Defender 排除（硬前置）**：Cygwin 与 LO 构建目录必须加入 Defender 排除项，
否则并行 configure 会删不掉 `conftest.dir` 而失败。

**产物定位**：`mergedlo.dll`（合并库）、`libreofficekit.dll`；运行期查找次序由 `ely_lok::ffi::KERNEL` 决定，
Windows 下会在该 DLL 所在目录的 `program/` 里一并搜索。

## 3. PDFium（PDF 内核）

- 取 **BSD-3-Clause** 的 Windows x64 二进制（Chromium 派生），登记来源与许可文本。
- **不使用** `pdfium-rs`（GPL-2.0-or-later）。
- 自写最小 FFI 绑定：`crates/ely-pdf-engine/src/pdfium.rs`，只覆盖首版所需：
  打开文档（内存/文件）、页数、页面尺寸、渲染页到 BGRA 位图、文本页（字符与外框）、
  搜索、关闭；写操作仍由 `lopdf` 完成。
- 保留 `ely-pdf-engine` 的 `ocr.rs`（Tesseract）、`marks.rs`/`redact.rs`/`sign.rs`/`structure.rs`/`secure.rs`/`output.rs`（lopdf 写层）与 `proto.rs`（IPC）。

## 4. 打包

| 产物 | 工具 | 许可要求 |
| --- | --- | --- |
| 单一离线安装器 `MPelyoffice-Setup.exe` | 自研 Rust 引导器 `apps/mpelyoffice-setup`（per-user，免管理员） | 附许可目录 |
| 分发目录（`MPelyoffice.exe` + `pdfium.dll` + 许可 + 清单） | `packaging/windows/stage.ps1` | 见下 |
| per-machine MSI | WiX（`dotnet tool global-install wix`，per-user 安装即可） | 同上 |
| 绿色版 zip | 直接打包 payload | 同上 |
| 源码包 | 自有源码 + `Cargo.lock` + `patches/` + 构建脚本 + LO 源码获取说明 | MPL-2.0 义务 |

### 4.1 分发目录的组成（`stage.ps1`）

```
MPelyoffice.exe            发行构建的界面
MPelyoffice-Setup.exe      发行构建的安装器
pdfium.dll                 PDF 内核（BSD-3-Clause，Chromium 的 PDFium）
MPelyoffice.json           逐文件的 sha256 清单
Licenses/LICENSE-MPelyoffice.txt   本项目许可（MIT）
Licenses/licenses.md                分发目录里的第三方许可
Licenses/PDFium-LICENSE.txt        PDFium 的许可
Licenses/rust-crates.txt            链进二进制的每个 crate 的许可（73598 行）
```

- 许可清单由 `packaging/crates.py` 生成（需 `PYTHONUTF8=1`），缺任何一份即打包失败。
- `stage.ps1` 取 `F:\mpely-target\release`（或 `debug`）里的可执行文件；引擎（LOK）未构建时会在日志里写明"尚未构建"，不静默跳过。
- 验收：`tests/scripts/mp-install.ps1`（装 → 跑 → 卸载，断言程序文件、文件类型、开始菜单项与卸载项都干净）。

**许可清单自动生成**（构建期阻断）：见 `06-格式支持矩阵与许可合规表.md` §3.3 的 LC-01..LC-06。

## 5. 签名与发布

| 通道 | 现状 | 计划 |
| --- | --- | --- |
| 本地/内部分发 | 未签名 | 内部测试可接受 SmartScreen 提示 |
| GitHub Releases | 未签名 | 取得 OV 证书（约 $150–300/年）或 Azure Artifact Signing（约 $9.99/月，无 USB 令牌，适合 CI）后签名**全部**二进制 |
| Microsoft Store | 不做 MSIX（与原生 DLL、插件目录、关联诉求冲突） | 不作为首发通道 |

**签名纪律**：全部二进制用**同一发布者身份**签名；每次发布后不修改已签名文件；
信誉按发布者 + 文件哈希双维度计算，每次新构建哈希归零，因此前几个版本预期仍有警告。

## 6. 常见故障速查

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| `link.exe not found` | VS 在非标准盘（`D:`），rustc 自动探测失败 | 先跑 `VsDevCmd.bat`；或设 `PATH/INCLUDE/LIB` |
| `embed-resource` 找不到 `rc.exe` | 缺 Windows SDK 组件 | 装 SDK 的 `VC.CMake.Project` 与 SDK 工具 |
| crates 下载极慢 | 直连 github/crates 仅 ~20KB/s | 设 `HTTPS_PROXY`；git 依赖设 `CARGO_NET_GIT_FETCH_WITH_CLI=true` |
| cargo 卡在 `Updating git repository` | libgit2 不走代理 | 同上，改用 git CLI |
| rustup 下载工具链极慢 | 同上 | 用已装工具链 + `RUSTUP_TOOLCHAIN` 覆盖 |
| LO configure 反复删不掉 `conftest.dir` | Defender 扫描 | 把 Cygwin 与构建目录加入排除项 |
| LO 构建认成 Git Bash | `MSYSTEM*` 变量污染 | 清除这些变量 |
| LO 取字体取到天亮 | `MORE_FONTS` 仍在 `BUILD_TYPE` 里 | 构建脚本已去掉；确认 `config_host.mk` 里没有 `MORE_FONTS` |
| worker 启动后无窗口/黑屏 | 缺图块补丁 `0044` | 确认补丁已打进 LO |
| LOK worker 载入表格即死锁 | worker 线程模型错误 | 用上游 `worker/messages.rs`（Windows 消息循环 + unipoll） |
| 界面乱码/字重不一 | DirectWrite 按用户区域选回退字体 | 保留 `vendor/gpui-pre-windows` 的 `text_locale` 修复 |
| 标题栏按钮点不动 | `WM_NCHITTEST` 取错窗口控制区 | 保留 `vendor/gpui-pre` 的命中测试修复 |
| **脚本点击总偏 1.25 倍** | 本机显示 125%，而 PowerShell 进程是 DPI-unaware，`SetCursorPos` 的坐标被系统按比例虚拟化 | 脚本里把目标坐标除以缩放（1.25）再调用；应用本身没有问题（`GetDpiForWindow`=120，坐标换算正确） |
| 中文输入法 `Ctrl+Shift+0` 无效 | 被输入法占用 | 改用 `Ctrl+Shift+9`（上游做法） |
| 发行版有黑色控制台窗口 | 未设 `windows_subsystem` | 发行构建设 `windows_subsystem = "windows"`；子进程用 `CREATE_NO_WINDOW` |
| 路径显示为 `\\?\C:\…` | `std::fs::canonicalize` | 用 `dunce::canonicalize` |

## 7. 与上游的关系

- 仓库为 ElyOffice 的 fork，upstream remote 保持可 rebase。
- 上游的 `AGENTS.md` 是其工程日志；本项目的文档在 `docs/mp/`，
  并在 `AGENTS.md` 追加 MPelyoffice 相关条目（上游规则："技术栈或产品方向变更时，同步改这个文件"）。
- 上游修复优先保留；本项目的改动以独立提交标记，便于回溯。
